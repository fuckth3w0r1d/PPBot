# 需求规格

## 目标与范围

PPBot 为 QQ 群成员提供文本指令、共享群上下文的 AI 对话和 B 站分享卡片解析。QQ 登录与消息收发由 NapCatQQ 承担，PPBot 通过 HTTP 接收消息事件，再调用 NapCat 的 HTTP API 发送回复。

业务范围限于群聊。私聊和非消息事件不产生业务回复。普通群消息无需 @ 机器人，也可由回复判定与概率筛选触发 AI 接话；未触发回复的群消息同样进入上下文。

本文规定 `dev/chat` 分支的目标行为与验收要求，不表示这些能力已经实现或完成外部联调。[架构说明](map.md) 和 [开发与运行指南](guides/development.md) 描述当前源码与运行现状，供定位实现和部署边界使用。

## 消息触发规则

有效群消息先记录到所属群的时间线，再判断业务处理方式。文本命令与符合条件的 B 站分享卡片由专用处理器接管，不能因扩大 AI 的触发范围而被抢占，也不再为同一事件发起判定或聊天请求。一个事件只执行一条业务回复路径；该路径可按原有方式发送多个消息段。

文本消息段会合并，并去掉开头的 ASCII 空格；命令名与参数通过 ASCII 空格分隔。文本命令无需 @ 机器人，且优先于 AI，例如 `@机器人 时间` 执行时间命令。AI 的直接唤醒、语义判定与概率筛选规则见下文。

## 文本命令

| 输入 | 结果 | 依赖与边界 |
| --- | --- | --- |
| `帮助` | 返回命令格式和已注册命令列表 | 列表顺序不固定 |
| `时间` | 返回 `YYYY-MM-DD HH:MM:SS` | 使用运行主机的本地时区 |
| `天气 城市` | 返回城市、天气、温度、风向、风力、湿度和报告时间 | 调用高德天气接口，只取首个城市参数；无参数时返回格式提示，查询范围为国内城市 |
| `随机二次元图片` | 以合并转发形式发送图片 | 图片接口须返回 `url` |
| `来点涩图 标签` | 将接口返回的多张图片以合并转发形式发送 | 标签传给图片接口，接口须返回 `proxyUrls` 字符串数组；示例配置与该接口要求不一致 |
| `吃啥` | 返回随机餐食文本 | 餐食接口须返回 `mealwhat` |
| `点歌 歌名` | 搜索第一首匹配歌曲并发送语音消息段 | 无参数时提示输入歌曲名称；依赖搜索和歌曲直链接口，不生成音乐卡片 |

天气、图片、餐食和音乐功能依赖各自外部接口。网络错误、返回空数据和字段变化的处理并不统一，不能保证每次失败都产生完整的用户提示。

**验收口径**：在 NapCat 收发可用时，群内直接发送 `帮助`、`时间` 应获得对应回复；发送 `天气` 或 `点歌` 应得到参数提示。外部接口配置满足实现要求时，带参数命令应返回表中类型的消息。

## AI 对话

### 模型分工

面向群成员只保留一个聊天模型，负责生成对话回复，并继续承担已有的群人格与用户画像总结。另接一个独立的小模型 API，仅判定消息是否明确需要机器人回应，不向群成员提供第二套聊天入口。

删除原 `ai2` 单次图文聊天及 `askAI` 路径，配置加载与示例不再要求原 `ai2` 配置。`/` 不再选择模型或无上下文模式，以 `/` 开头的非命令文本与其他文本遵循相同的触发与上下文规则。判定模型不能作为聊天模型的备用回复服务，也不能由群成员选择使用。

本规格的媒体上下文以文本和消息类型标记为边界，不要求自动识图、语音识别或理解视频内容。删除原单次图文入口不代表聊天模型已经具备图片理解能力。

### 回复分流

下表适用于未由命令或 B 站卡片处理器接管的群消息。

| 场景 | 模型调用与回复要求 |
| --- | --- |
| 明确 @ 本机器人，并有非空文本 | 绕过判定模型与概率筛选，直接调用聊天模型并回应 |
| 能确认引用了本机器人的消息，并有非空文本 | 绕过判定模型与概率筛选，直接调用聊天模型 |
| 直接唤醒但文本为空，包括仅 @ 或仅附图片 | 返回输入提示，不发起模型请求 |
| 其他有可判定文本的群消息 | 先调用判定模型，判定为明确应回应时直接进入聊天模型 |
| 判定为非明确应回应 | 进入本地概率筛选；未抽中则沉默，抽中则调用聊天模型，由其结合语境决定回复或沉默 |
| 判定请求超时、网络失败或结果无效 | 记录判定失败，按无法明确判断处理，进入同一概率筛选路径 |
| 无可判定文本且未直接唤醒 | 仅记录消息，不发起模型请求或输入提示 |

@ 本机器人要求消息段中的 QQ 与配置的机器人 QQ 一致；@ 其他成员、@ 全体以及引用其他成员的消息都不能据此直接唤醒。引用直接唤醒必须能够确认被引用消息来自本机器人，不能只因消息含有引用段就触发。机器人的出站回复进入上下文，但不能再次触发自身回复。

聊天模型须知道本轮属于直接唤醒、判定通过还是概率插话。@ 时必须回应；概率插话允许保持沉默，不能将沉默结果或判定标签作为群消息发送。直接唤醒不依赖判定服务的可用性，判定失败不额外重试，也不另行调用聊天模型充当判定模型。聊天模型请求失败不得生成虚假的成功回复记录；已有入站群消息仍须保留。

### 判定输入与输出

判定输入包含机器人的身份、名称及当前人设、群内角色和相关群人格，以及当前消息与本群的近期短上下文。短上下文保留发言人、机器人回复、@ 和引用关系，使判定能够识别直接呼叫、补充和追问，例如结合上一轮理解“那第二种呢？”。判定所用人设复用聊天机器人的人设来源，不另行维护一套角色设定。

判定模型从同一份群时间线截取较短窗口，不复制全部长期历史或用户画像，不建立独立的长期会话。当前消息在输入中只出现一次。固定判定职责与所提供的人设、群消息内容分开，模型分析这些材料并只输出固定、可解析的判定结果，不扮演机器人聊天，也不输出长解释。表示“非明确应回应”的结果允许后续概率插话，不等于禁止任何回复。

呼叫、补充和追问由语义判定结合上下文识别，不以“机器人刚回复后某个固定时长内，同一用户的所有消息都直接触发”代替判定。

### 共享群上下文

历史以群为边界组织成按接收顺序排列的时间线。记录应保留群号、消息标识、发言人 ID 与显示名、时间、文本、可用的 @ 与引用关系。图片、语音、视频和卡片等非文本内容保留类型标记及可用的文本信息，不把标记当成已经理解的媒体内容。命令、卡片和未回复的普通消息都属于群上下文。

聊天请求读取所属群的共享历史，不再局限当前发言人的个人问答。例如甲提供信息后，乙向机器人提问时，模型可以看到甲在窗口内的原始发言，并知道两者是不同成员。群号必须精确匹配，任何其他群的消息、人格和画像均不得混入。

聊天模型接收系统人设、本群人格、相关用户画像及裁剪后的群历史。判定模型使用同一历史中的短窗口，聊天模型使用较长窗口。两者均限制消息数量和总输入长度；预算包含人设、画像、元信息和消息内容，并为输出预留空间。超出预算时裁剪最早的历史，保留当前消息与必要的身份信息，不承诺一次请求可见无限历史。普通插话概率、上下文窗口与输入预算通过配置确定。

同一群的请求与历史更新须保持一致的消息边界：当前输入不能重复追加，生成期间到达的新消息不能在完成回复时被覆盖或漏记。机器人实际发送成功的回复进入群时间线；尚未发送或发送失败的生成内容不能被当作群成员已经看到的发言。用户画像仍按群内成员区分，群人格仍按群区分，不能将其他成员的话归为当前用户的个人特点。

### AI 验收要求

分流验收使用可控制返回结果的模型服务与可控制的概率结果，检查请求次数、请求内容和实际出站消息。不能以随机试发几次是否碰巧回复作为分支通过的依据；真实模型的语义效果另用呼叫、追问和成员间对话等样例评估。

| 场景 | 验收结果 |
| --- | --- |
| `@机器人 时间`、普通文本命令或符合条件的 B 站卡片 | 专用处理器完成原有回复，无判定或聊天请求；事件仍进入群历史 |
| @ 本机器人并提问，或确认引用机器人回复并提问 | 直接调用聊天模型，判定模型零次调用，概率筛选不影响触发；@ 必须回应 |
| 仅 @ 本机器人 | 返回输入提示，不调用任一模型 |
| 仅 @ 其他人、@ 全体或引用他人 | 不因这些消息段直接唤醒，按普通消息的文本条件处理 |
| 判定模型返回明确应回应 | 调用聊天模型，不经过概率筛选 |
| 判定模型返回非明确应回应，概率未命中 | 不调用聊天模型，不发送回复，入站消息仍被记录 |
| 判定模型返回非明确应回应，概率命中 | 调用聊天模型；其选择沉默时没有出站消息，选择回复时正常发送 |
| 判定模型超时、网络失败或返回无效结果 | 记录失败，分别验证概率命中与未命中路径；无判定重试或额外的主模型判定请求 |
| 判定服务不可用时 @ 本机器人 | 仍直接调用聊天模型，不等待判定服务 |
| 机器人回复后，成员发出无 @ 的补充或“那第二种呢？” | 判定请求包含可识别发言人的近期用户与机器人消息，能够据此作出是否明确应回应的判定 |
| 甲发言后乙提问，另有其他群的消息 | 当前群请求包含窗口内甲的发言和乙的当前输入，各出现一次；不包含其他群的消息、人格或画像 |
| 消息超出窗口或输入预算 | 保留最新可容纳历史和当前消息，请求符合预算；判定模型使用较短的同源窗口 |
| 聊天模型生成期间同群继续收到消息 | 新消息不被完成回复的更新覆盖或漏记；未发出的回复不冒充已发送消息 |
| `/问题` 或无原 `ai2` 配置启动 | 不再切换模型或进入无上下文图文入口；没有让用户选择判定模型聊天的入口 |
| 未直接唤醒的纯图片、语音等消息或机器人自身回复 | 保留对应上下文记录；不产生无意义的输入提示或机器人自我触发 |

## B 站分享卡片

群聊中的 JSON 卡片在未匹配文本命令，且 `meta.detail_1.appid` 与配置一致时，由 B 站处理器接管。程序从分享短链的重定向地址提取 BV 号，获取视频信息和播放地址，发送封面、统计文本，并尝试下载和发送视频。视频下载失败时，在回复中增加下载异常文本。

该功能依赖卡片结构、短链的 HTTP 302 响应和 B 站接口字段，不处理任意文本视频链接。视频通过本地 `file://` 路径交给 NapCat，双方必须能读取同一缓存文件路径。

**验收口径**：在卡片和接口均符合实现要求、缓存目录可写且 NapCat 可读取文件时，分享卡片应产生封面、视频信息和独立视频消息；其他应用卡片不由 B 站处理器产生回复，其中独立文本仍按相应文本触发规则处理。下载超限或失败时，应出现下载异常文本。

## 数据与运行约束

PPBot 以单进程运行，沿用本地 JSON 与定时保存方式持久化群历史、群人格、用户画像和相关计数。新群时间线从新功能上线后收到的消息开始积累，不主动拉取上线前或停机期间的平台历史。即使群内没有触发任何 AI 请求，新入站消息也必须进入保存范围；重启后恢复已经成功保存的群历史。

旧的按用户组织的历史缺少可恢复群聊顺序的时间信息，保留原文件，不伪造时间顺序混入新时间线。已有群人格与群内用户画像继续复用。周期保存不等于送达保证或跨文件事务；未成功保存的数据仍有丢失风险。当前文件格式、停机边界和目录管理见 [开发与运行指南](guides/development.md)。

**持久化验收口径**：使判定全部返回非明确应回应、概率全部不命中，只发送普通群消息；确认这些消息保存成功后重启，后续聊天请求仍能读到窗口内记录。跨群记录继续隔离，旧个人历史文件不被清空或覆盖，新时间线中没有伪造的旧消息。

消息、回复、画像和人格以明文进入数据文件或日志。未 @ 机器人的普通群消息也会发送给配置的判定服务；聊天服务收到选取的群历史、人设与画像。新增判定调用会增加 API 开销与响应等待，不能仅凭模型参数量承诺总费用降低。

判定服务通过独立部署配置提供服务地址、鉴权信息、模型与请求超时等必要参数，不将具体供应商或模型型号固化为产品行为。沿用现有启动时加载配置和重启生效的方式；本规格不要求新增配置热加载、数据库、向量检索、自动补抓历史或任务队列。

消息收发与外部接口的现有运行约束仍以 [开发与运行指南](guides/development.md) 和 [架构说明](map.md) 为准。上报接口返回成功不代表 QQ 回复已经送达。
